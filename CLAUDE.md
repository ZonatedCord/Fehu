# Fehu — Project Notes for Claude

## Release process

### How to ship a new version

1. Make all commits to `main`
2. Bump version in **both** files:
   - `src-tauri/tauri.conf.json` → `"version": "X.Y.Z"`
   - `src-tauri/Cargo.toml` → `version = "X.Y.Z"`
3. Commit: `chore: bump vX.Y.Z`
4. Push main, then tag:
   ```
   git push origin main
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```
5. CI builds all platforms (~10 min) and auto-uploads artifacts + `latest.json`

### Moving an existing tag (hotfix mid-release)

```bash
git tag -d vX.Y.Z
git push origin :refs/tags/vX.Y.Z
git tag vX.Y.Z
git push origin vX.Y.Z
```

### latest.json

`latest.json` is required for the in-app updater (Tauri plugin-updater).
It is generated by the `create-update-manifest` job in `.github/workflows/release.yml`
after all build jobs finish. The job downloads the release artifacts, re-signs them
with **Tauri CLI** (`tauri signer sign`) using `TAURI_SIGNING_PRIVATE_KEY`, then builds the manifest.

**Why Tauri CLI and not minisign binary:** `minisign` CLI cannot parse `TAURI_SIGNING_PRIVATE_KEY`
format ("Error while loading the secret key file"). `tauri signer sign` reads the same env var
natively — same as the build step.

**Why we sign in the manifest job instead of uploading from build:** `tauri-apps/tauri-action@v0`
logs "Signature not found for the updater JSON. Skipping upload..." for Tauri 2. The `.sig` files
exist on disk but `find src-tauri/target -name "*.sig"` returns nothing (root cause unknown).
Signing in `create-update-manifest` is the reliable workaround.

**If the updater shows "Could not fetch a valid release JSON" or "Invalid encoding in minisign data":**
- Check that `latest.json` exists in the GitHub release assets
- Check that the CI `create-update-manifest` job succeeded (it runs last)
- If signatures are empty in `latest.json`, the signing step failed — check `tauri signer sign` output in CI logs
- The signing uses `tauri signer sign` with `TAURI_SIGNING_PRIVATE_KEY` env var
- The script generating the manifest is at `.github/scripts/gen_latest_json.py`

The in-app updater only triggers if `latest.json` version > installed version.
Rebuilding the same version tag does NOT trigger an update prompt.

**After an in-app update on macOS:** Spotlight may still show the old dev build at
`src-tauri/target/release/bundle/macos/Fehu.app`. Delete it or it will show up in Spotlight
as a second "Fehu.app (macos)" entry. The correct installed app is `/Applications/Fehu.app`.

### CI workflow notes

- Workflow file: `.github/workflows/release.yml`
- 3 build jobs (aarch64-apple-darwin, x86_64-apple-darwin, windows) run in parallel
- `create-update-manifest` runs after all 3 succeed (`needs: build`)
- YAML heredocs with Python code cause parse errors → use external script instead
- TAURI_SIGNING_PRIVATE_KEY must be set as GitHub secret (key at `~/.tauri/fehu.key`)
- Transient curl failures on aarch64 runner (network errors downloading Rust crates) — retag to rerun

## Telegram bot

- Script: `sidecar/fehu_bot.py` (aiogram 3, FSM-based)
- Bundled as Tauri resource in production: `tauri.conf.json` → `bundle.resources`
- Bot is killed on window close via `pkill -f fehu_bot.py` (SIGTERM) then `pkill -9` after 1.5s
- Dep check validates aiogram 3+ FSM API (`from aiogram.fsm.context import FSMContext`)
- Bot stdout/stderr redirected to `/tmp/fehu_bot_app.log` when spawned from app (for debugging)

### Bot kill strategy — CRITICAL

Using `pkill -9` (SIGKILL) before starting a new bot causes **Telegram 409 Conflict**:
the old session isn't cleanly closed, new bot gets "Conflict: terminated by other getUpdates"
and crashes immediately. **Always use SIGTERM first, wait ≥1500ms, then SIGKILL stragglers.**

Current implementation in `src-tauri/src/commands/telegram.rs`:
1. `pkill -f fehu_bot.py` (SIGTERM) — lets aiogram close polling cleanly
2. Sleep 1500ms
3. `pkill -9 -f fehu_bot.py` (SIGKILL) — kills any that didn't respond to SIGTERM
4. Sleep 500ms
5. Spawn new bot

### FSM state loss on restart

Bot uses `MemoryStorage` — all FSM states lost on restart. Stale inline keyboard buttons
from old sessions trigger `KeyError: 'tx_type'` without the guard. Fixed in `_expired()`:
all aggiungi callbacks check `data.get("amount")` and show "Sessione scaduta" if empty.

### Bot flow: /aggiungi

Multi-step FSM: amount+description → categories keyboard → Contanti/Carta → notes (type OR tap Salta) → confirm → saved.
- Notes step: user types text directly in Telegram chat (no special input box)
- Old session buttons show "Sessione scaduta. Riprendi con /aggiungi."

### Debugging bot crashes

When bot is started from app (not terminal), output goes to `/tmp/fehu_bot_app.log`.
To test bot independently: `python3 /Applications/Fehu.app/Contents/Resources/sidecar/fehu_bot.py --token TOKEN --db-path "~/Library/Application Support/dev.fehu.app/fehu.db"`

If token field in Settings contains garbage (terminal output, spaces), bot fails with
"TokenValidationError: Token is invalid! It can't contains spaces." — re-enter token from @BotFather.
